### P0-1：认证状态非响应式（产品级 bug，必须修）
**根因**：`frontend\src\api\client.ts` 第 21 行 `let accessToken: string | null = null` 是模块级普通变量（非响应式）；`frontend\src\stores\auth.ts` 第 38 行 `const isAuthenticated = computed(() => getAccessToken() !== null)` 依赖它。Vue 的 computed 无法追踪非响应式依赖 → 首次求值（初始 `/login` 页，无 token）得到 `false` 后被永久缓存，`router.beforeEach`（`frontend\src\router\index.ts` 第 108 行）的 `to.name === 'login' && auth.isAuthenticated` 因此永远不成立，登录成功后 `router.replace('/')` 被守卫再弹出 → 用户被踢回 `/login?next=/`。真实用户同样受影响（只能手动刷新页面靠 refresh cookie 进入）。

**改法（推荐：单一数据源，避免双写不一致）**：
1. `frontend\src\api\client.ts`：顶部 `import { shallowRef } from 'vue'`；第 21 行改为 `const accessToken = shallowRef<string | null>(null)`；`setAccessToken` → `accessToken.value = token`；`getAccessToken` → `return accessToken.value`；`buildHeaders` 第 72 行的判定改为 `accessToken.value`；`__resetClientState` 中改为 `accessToken.value = null`；顶部注释补一句说明用 shallowRef 是为了让 auth store 的 computed 能响应式感知。
2. `frontend\src\stores\auth.ts`：第 38 行保持不变即可（改为读响应式 ref 后自动生效）。
3. 验证不要只看单测：必须在浏览器里确认「登录成功后直接进入 `/`、URL 不含 login」。

### P0-2：登录失败提示被自己清掉（功能 bug，必须修）
**根因**：`frontend\src\views\LoginView.vue` 第 67-69 行，`onLogin` 的 catch 里先 `error.value = toApiError(caught)`，紧接着 `await loadCaptcha()`，而 `loadCaptcha()` 第 41 行首句就是 `error.value = null` → 错误提示刚赋值就被清空。实测：后端正确返回 401 `UNAUTHENTICATED`（message「邮箱或密码不正确。」），前端 `.el-alert--error` 计数为 0。`onRegister` 第 91-93 行有同样缺陷。

**改法**：`onLogin` / `onRegister` 的 catch 均改为「先算 error → 再 await loadCaptcha() → 最后回填 error」：
```ts
} catch (caught) {
  const apiError = toApiError(caught)
  await loadCaptcha()    // 刷新验证码（内部会清空 error）
  error.value = apiError // 之后再回填，保证用户可见
}
```
`finally { loading.value = false }` 保持不变。

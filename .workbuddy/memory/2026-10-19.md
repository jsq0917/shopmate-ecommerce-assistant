### 关键决定与坑

1. `BGEM3FlagModel` 该版本参数是 `devices` 而不是 `device`；传错会被吞进 `**kwargs`。
2. BAAI/bge-m3 仓库只有 `pytorch_model.bin`（2.27GB）+ `sparse_linear.pt`/`colbert_linear.pt`，没有 safetensors；一开始忽略 `*.bin` 导致只下到 22MB 配置。HF 直连 502，走 `hf-mirror.com` 且必须 `HF_HUB_DISABLE_XET=1`（xet CAS 401），最后用 curl 直链下载。
3. 证据门槛不能用 RRF 分数（乘性），改用候选 chunk 的 dense 余弦重打分（复用查询向量 + `chunk_id in [...]` 过滤检索，无需重新编码）。0.42 时 3 条无答案误答，按实测分布（无关 0.5836 / 相关 0.6961）标定为 0.62。

5. 消融对照结论必须如实：双路与 dense-only 指标持平（17 条中 12 条排序不同，但 top-1 不变），不能宣称提升。

### 两个根因（均有代码级+运行时证据）
1. **`src/stores/auth.ts` `isAuthenticated` 是包着非响应式 `getAccessToken()`（client.ts 模块级 let）的 computed**：router 守卫第 3 条 `to.name==='login' && auth.isAuthenticated` 在初始 /login 页首次求值 → 无 token → 缓存 false 永不更新 → 登录成功（login 200 + /auth/me 200）后 `router.replace('/')` 被守卫弹回 `/login?next=/`。**真实用户同样被弹回（须手动刷新页面靠 refresh cookie 才能进）**。最小修复：client.ts 用 `shallowRef` 存 token 并导出响应式引用，store computed 改读它。
2. **`src/views/LoginView.vue` catch 里 `error.value = toApiError(...)` 后紧跟 `await loadCaptcha()`，而 loadCaptcha 首行 `error.value = null`** → 登录失败提示被清掉（错误密码场景无 alert；debug 见 captcha 刷新 200 但 ALERTS:[]）。最小修复：catch 中先 await loadCaptcha() 再赋值 error。

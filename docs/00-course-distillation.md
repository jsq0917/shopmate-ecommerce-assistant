## 2. 可借鉴的产品要求

以下要求与 ShopMate 的 MVP 目标方向一致，可以转化为本项目自己的需求与验收标准：

1. **中文全栈体验**：前端、后端提示词、错误提示和演示流程必须保持一致的中文体验。
2. **完整账号与会话链路**：注册、登录、图形验证码、会话创建/重命名/删除、短期历史和会话归属校验。
3. **多知识库与文档管理**：允许按知识库选择检索范围，支持上传、解析、分块、预览和治理文档。
4. **文档格式覆盖**：PDF、DOCX、PPTX、Markdown、TXT 为 MVP 基线；图片/OCR 作为可选扩展，不阻塞核心链路。
5. **检索参数可解释**：分块大小、重叠大小、检索模式、返回数量和模型参数应通过受控配置管理，并在评测中调整。
6. **流式回答**：后端提供稳定的事件协议，前端逐步渲染，同时保留取消、错误和结束事件。
7. **可演示性**：关键用户旅程需要端到端脚本、合成数据、固定随机种子和可复现的启动说明。
8. **质量门禁**：重要功能必须有自动化测试；修改后运行测试，不能只依赖手工页面检查。
9. **可观测性**：结构化日志、请求追踪、错误码和延迟记录是完整链路的一部分。
10. **项目价值**：演示应展示真实数据链路和可验证证据，而不是只展示聊天 UI 或宣传数字。

## 3. 可借鉴的 RAG 工程方法

课程资料体现了“先分层，再做可评测链路”的思路。ShopMate 采用其中与电商客服直接相关的部分：

| 层次 | 可借鉴方法 | ShopMate 的落地边界 |
|---|---|---|
| 加载与解析 | 多格式解析、版面/表格保留、失败可见 | 解析失败不得生成空知识库；文件必须进入受控目录并重命名 |
| 分块 | 标题层级、段落边界、父块/子块、重叠 | 配置化父块/子块大小；子块保留父块、页码、标题路径和原文哈希 |
| 向量化 | dense + sparse/lexical 双路召回 | provider 可插拔；测试使用 fake provider，不依赖真实外部模型 |
| 检索融合 | 讲义中的 dense + sparse 混合检索与重排；ShopMate 合同要求 RRF | 采用可解释的 RRF 或等价融合；所有过滤条件显式、可测试 |
| 问答生成 | 历史感知、中文提示词、流式输出 | 上下文明确区分系统规则、工具事实和不可信文档片段 |
| 引用 | 文档、章节/页码、版本、生效日期、片段 ID | 政策回答没有足够引用时拒答或转人工 |
| 工具 | 订单、物流、退货、转人工等受控调用 | 模型不能直接访问数据库；用户身份和店铺范围由后端注入 |
| 评测 | Recall@k、context precision/recall、faithfulness、answer relevancy | 评测结果必须保存原始数据和配置；不得把课程示例值当成本项目结果 |
| 工程化 | Docker Compose、健康检查、接口文档、日志和测试 | 使用固定镜像版本、named volumes、健康依赖和环境变量 |

## 4. 与 ShopMate 合同一致的方向

以下内容直接吸收到后续阶段，不改变 `AGENTS.md` 的优先级：

- 模块化单体 + 单 Agent + 确定性工具层，不拆微服务。
- 结构化事实（价格、库存、订单、物流、优惠）只来自 PostgreSQL、受控缓存或 Mock OMS。
- 政策 RAG 必须带文档、章节/页码、版本、生效日期和片段 ID。
- 金额、退款资格和退款申请由确定性规则决定；LLM 只解释结果。
- 投诉、法律威胁、异常订单、低置信度和用户要求人工时升级。
- 写入操作需要幂等键和审计记录，且只写申请或模拟状态。
- 前端只能调用公开 API，不直接连接 PostgreSQL、Redis 或 Milvus。

## 5. 明确不照搬的内容

### 5.1 技术栈冲突

- 课程 `CLAUDE.md` 写的是 Python 3.13+；本项目合同固定 Python 3.12，且 `.python-version` 已为 `3.12`。以本项目合同为准，不升级运行时来迁就课程示例。
- 课程任务描述使用 MySQL；本项目固定 PostgreSQL 16，差异必须记录在 ADR，而不是同时引入两套主数据库。
- 课程示例的静态 HTML/React 草案不等同于本项目要求的 Vue 3 + Vite + TypeScript；前端不能直接复制。
- 课程示例中出现的具体模型、模型权重和 OCR 方案不作为本项目默认依赖；先定义 provider 接口和测试替身。

### 5.2 来源、安全与宣传数据风险

- `config.py` 中存在模型绝对路径、数据库/Redis 默认凭据等硬编码风险。本项目不得复制具体值，必须使用 `.env`、环境变量和相对路径。
- 不复制未核验许可证的代码、配置、提示词、测试和数据。
- 不读取、复制或提交参考项目中的真实 `.env`、API Key、数据库凭据、数据库、日志和模型权重。
- 不读取、复制或提交真实用户数据、真实 PII、完整手机号、地址、身份证、银行卡或支付信息。
- 电商场景中的“82% 自助解决率”“42% 缓存命中率”“70% 成本降低”“18% 转化率提升”均为示例宣传值，不是 ShopMate 实测结果，禁止写入 README、演示、评测或简历。
- 场景材料中的客服规模、SKU/FAQ 数量、模型微调、RAGAS 分数、ROI、GMV 和人工工单下降比例同样不得当作 ShopMate 结果。
- 不复制课程宣传指标、参考仓库 README 自报指标或 benchmark 数字。
- 不照搬“10 万条真实客服对话微调”等需要真实 PII 或模型训练的做法；ShopMate 只使用 synthetic/mock 数据和 fake provider。

### 5.3 工程实现不能照搬

- 不复制课程中的 `eval()` 配置读取、宽泛异常捕获、全开放 CORS、前后端端口不一致等实现。
- 不照搬“只做聊天 UI”或“让模型直接回答实时事实”的做法。
- 不把 LangChain/LlamaIndex 当作不可见黑盒；核心流程必须在本项目代码中可读、可测。
- 不以课程评分规则替代本项目验收标准。评分维度可作为演示设计参考，但每个 MVP 功能仍需定义可测试验收条件。
